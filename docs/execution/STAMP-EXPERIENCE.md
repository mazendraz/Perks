# L06A — سكان وختم لحظي

التنفيذ المحلي للعميل المسجل موجود. شاشة أول مرة بالاسم والرقم واستكمال الجلسة من الجهاز تابعان لـL06B؛لا يُحسب مسار التسجيل القديم قبولًا لهما. موافقة المالك على فيديو من موبايل حقيقي،والكاميرا وNFC والتثبيت الفعلي،ما زالت BLOCKED_OWNER في L08.

## الاستخدام

`/p/{code}?src=qr|nfc` يفتح الكارت الموجود بدون زر وسيط،ويحفظ سياق القطعة والفرع. الطلب يخرج تلقائيًا بنفس المفتاح عند فقد الاتصال،لمدة أقصاها10دقايق؛تكرار السكان يعيد الطلب المعلق،والـrefresh بعد نجاحه لا ينشئ طلبًا جديدًا. الفرع المقفول والقطعة الملغية يعرضان توجيهًا واضحًا.

الكاشير يقرأ QR العميل القصير،ويُدخل الإيصال،ثم يعتمد الطلب بضغطة واحدة بلا نافذة تأكيد. proof القراءة مربوط بالكاشير وجلسةه والفرع وصلاحية كود العميل؛البحث وحده لا يجيز ختمًا أوصرفًا. «تراجع» خلال10ثواني يطلب تصحيحًا تعويضيًا ومراجعة المدير،ولا يمسح Ledger أويلغي مراجعتها. الكسب من السكان العادي يغلق الطلب المعلق المطابق داخل نفس transaction. تأكيد الحامل قبل صرف المكافأة مستمر،وبعد الصرف يبدأ الكارت التالي مع حفظ الفائض وفق البرنامج.

## التحديث وحدود الطلب

اتصال LISTEN واحد لكل process،مع إشعارات transaction-bound IDs فقط للـledger والطلبات وتأكيد الصرف. SSE يعيد فحص الجلسة وصلاحية الفرع وRLS قبل التسليم،heartbeat25s،وsync عند الاتصال،وpolling3s عند فشله. العميل يقرأ التفاصيل من API الخاص المعتاد. Caddy يستخدم flush_interval=-1. ليست هناك queue أحداث خاصة محفوظة في المتصفح.

الحد الافتراضي10طلبات لكل عميل/محل/يوم محلي،ويمكن للمالك تغييره1–100. القفل يمتد عبر البرامج لمنع سباق الحد،والمحاولة الزائدة تتسجل في audit دون rollback لواقعة المنع. إعداد المالك محمي بالدور وCSRF وOrigin وrevision.

## الحركة والحفظ

مرجع الحركة [stamp-motion-v2](../design/stamp-motion-v2.html) فُتح في Chromium قبل التنفيذ. WAAPI: ظهور120ms ثم نزول180ms وخبطة،squash120ms ورفع220ms؛الحبر220ms والختم التالي بعد350ms والعداد بعد300ms. الرسم يُشتق من ledger ID وunit ordinal ويثبت بعد reload،مع36نقطة و7specks وgrain35% وزاوية±8°. ألوان وشكل وأيقونة المحل هي المصدر. المكافأة لها banner فوق الكارت وcanvas واحد44قطعة/1.3s. reduced-motion يملأ فورًا بلا أداة أوconfetti أوvibration. لا صوت للختم. صوت تنبيه طابور الكاشير اختياري ومقفول افتراضيًا.

ظهور الكارت الأول720ms ولا يمنع التفاعل. QR العميل في شاشة بيضاء كاملة،يتجدد قبل انتهاء صلاحيته ويُغلق عند الختم المؤكد. رد QR متأخر بعد الإغلاق لا يعيد فتحه. تذكير الحفظ يظهر بعد أول كارت،ثم بعد أول ختم إذا رُفض،ولا يتكرر تلقائيًا بعد ذلك. Safari له دليل مرسوم بخطوتين؛standalone يخفي التذكير. manifest يبدأ من/customer. لا ادعاء بأن التثبيت أوضبط سطوع الشاشة تم تلقائيًا.

لوحة التاجر تعرضp95 فتح الكارت من قياس الجهاز،وp95 اعتماد الطلب من وقت السيرفر،ونسبة الطلبات المنتهية بلا اعتماد مع استبعاد pending،ومحاولات تجاوز الحد. قياس الجهاز ليس إثبات شراء أوSLO إنتاجيًا،والعينات الفارغة تُعرض بشرطة.

## إعادة الفحص

- `npm run test:integration`: تشمل live-events وrequests وrequest-limits وrewards للعزل والتزامن والإلغاء والرجوع والفائض وثبات الرسم.
- `npm run test:e2e`: رحلة الكاشير inline،فقد الرد بعد الحفظ،reload ثم scan جديد عند عدم الحفظ،وتأكيد الصرف والكارت التالي.
- `npm run test:e2e:mobile`: legacy build وCSP الفعلي على Chromium/Pixel5 وWebKit/iPhone12؛خمس سكانات بلا ضغطات وطلب واحد،قطع قبل/بعد الحفظ،تجديد QR،ثبات الرسم والتثبيت وحدوده،والفرع المقفول وNFC الملغي. fixture WebKit تمنع Service Worker لتتاح محاكاة أعطال الشبكة؛اختبار shell offline وCacheStorage والتحديث الفعلي يعمل على Chromium. هذا قيد أداة الاعتراض [الموثق في Playwright](https://playwright.dev/docs/api/class-browsercontext#browser-context-route)،ولا تعديل به لسلوك التطبيق.
- `npm run test:animation`:24فريمًا مثبتًا بجوار المرجع،ثم بناء fixture إنتاجية بنفس legacy/CSP وtrace Pixel5/CPU4x بحد32ms. النتائج في evidence/animation. نجاح المحاكاة لا يغلق شرط الفيديو الحقيقي.
- `npm run verify:local`:القبول الجامع وبصمة السورس. تقرير failed أوsource_changed لا يُحسب قبولًا.

كل الاختبارات تستخدم بيانات صناعية منفصلة عن قاعدة تجربة مازن. `standalone/` والأدلة الأصلية لا تُحرَّر يدويًا،والأدلة الجديدة مولدة من الأدوات. تعليمات التشغيل المادي في [PILOT-RUNBOOK](PILOT-RUNBOOK.md).
