# الدخول الجديد والواجهة — 2026-11-08

بناءً على طلب مازن، الدخول العادي لكل الأدوار أصبح **إيميل وباسورد**: مدير المنصة،مالك الشركة،الكاشير والعميل. لا يُطلب OTP أوAuthenticator. التسجيل العام ينشئ customer فقط؛دعوة النشاط وقبولها هي التي تمنح المالك/الموظف دوره وفروعه. صفحة الدعوة تعرض إنشاء الحساب واختيار الباسورد أول مرة،أوالدخول لحساب موجود.

حساب مازن `mazen@nuqta.test` له باسورد أولي عشوائي داخل الملف الخاص `.local/manual-demo/login.txt`. حسابات التطوير القديمة تُجهّز عبر `db:seed` بباسوردات عشوائية في `.local/seed-logins.txt`. إعادة الإعداد لا تغيّر باسورد اختاره المستخدم بالفعل،ولا تمس الشركات أوالكروت والأرصدة. ملفات بيانات الدخول لا تتقدم عبر HTTP ولا تدخل Git أوتقارير الأدلة. يمكن تغيير الباسورد من حسابي.

## التخزين والجلسات والاستعادة

- Migration `009k_password_auth.sql` تضيف password hashes وcredential versions ونوع الجلسة وحواجز المحاولات وتوكنات الاستعادة. تُلغى الجلسات القديمة عند تطبيقها؛لا بيانات ولاء تُصفّر.
- scrypt بإعداد N=32768 وr=8 وp=3،salt عشوائي لكل حساب،ومدخل HMAC بمفتاح pepper منفصل. التنفيذ بحدود تزامن للذاكرة،ومقارنة ثابتة الوقت. لا plaintext في DB أوlogs. إعداد KDF أحد الخيارات الموصى بها في [OWASP Password Storage](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)،ويستخدم [Node crypto](https://nodejs.org/docs/latest-v24.x/api/crypto.html).
- الباسورد من 12 إلى128 محرفًا،دون شروط تركيب معقدة أومنع لصق. تسجيل الدخول يحافظ على القيمة كما كتبها المستخدم،ويدعم العربية. 5 محاولات خاطئة تقفل الحساب مؤقتًا15دقيقة،مع حد مستقل لطلبات IP. الرد على كلمة خطأ أوحساب غير معروف/موقوف عام.
- الحسابات تُقرأ بصلاحيات Auth فقط. runtime لا يقرأ hashes،ولا يمكن للتسجيل أن يمرر global role. كل طلب أعمال يراجع الدور والفرع الحاليين حتى لو جلسة Password فعالة.
- Cookie HttpOnly وSameSite وOrigin وCSRF ما زالت مطلوبة. `credential_version` يربط كل جلسة بنسخة بيانات الدخول؛تغيير كلمة المرور أوالاستعادة يلغي الجلسات الأقدم. إصدار جلسة بعد التحقق يفحص النسخة ثانيةً لمنع سباق تغيير الباسورد أثناء الدخول.
- تغيير الباسورد يتحقق من الحالي،ويلغي الجلسات السابقة ويصدر cookie وCSRF جديدين للمتصفح الحالي.
- نسيت كلمة المرور تعيد202 عامة،وتضع رابطًا عالي العشوائية لمدة30دقيقة في البريد المحلي. المخزن هو hash التوكن،واستخدامه مرة واحدة يرفع نسخة الباسورد. السباق بين طلبين ينجح مرة واحدة،والروابط السابقة تصبح غير صالحة بعد تغيير البيانات. البريد المحلي داخل الذاكرة؛لو الخدمة أُعيد تشغيلها قبل فتح الرابط،اطلب رابطًا جديدًا.
- مسارات OTP القديمة تُرفض في development. اختبار التراجع القديم فقط يستخدمها في APP_ENV=test،وحساب له password hash لا يستطيع الدخول بها. TOTP القديمة لا تمنح password sessions أي صلاحية إضافية. Supabase/managed adapter ما زال مسارًا منفصلًا غير مكتمل؛production/staging يرفضان local auth كما كان.

## تصميم المنتج

صفحة دخول بتحرير بصري واضح ومساحة عضوية مميزة،دون بيانات تسويقية أوإحصاءات مزيفة. خطوط IBM Plex Sans Arabic وManrope محلية مع رخص OFL وبصمات المصدر في `apps/web/public/fonts`. لا طلبات خطوط لطرف خارجي عند الاستخدام.

قوالب الكارت أصبحت ثلاثة تعبيرات لهوية النشاط:classic بدفء وألوان العلامة وتفاصيل محفورة،minimal بسطح هادئ،وbold بمعالجة أكبر للعنوان والأختام. لكل كارت علامة النشاط والعضو ورقم الدورة والأختام ومؤشر التقدم والمكافأة. اختيار لون نص داكن/فاتح يعتمد على سطوع اللون. البيانات والحركة ما زالتا مربوطتين بـrevision مؤكد؛الفائض وحقوق المكافآت محفوظة.

التنقل الرئيسي له أيقونات ومساحة عمل محددة،مع بيانات فعلية فقط. أول شركة لها empty state واضح مع زر بدء تجهيز،ومحطة الكاشير تبدأ بقراءة الكارت،والعميل على desktop يرى الكارت بجوار العمليات والمكافآت. المقاييس تعرض معلومات بدرجات أهمية بدل صف من لوحات متطابقة. RTL/LTR و390px وreduced-motion محسوبة في التصميم.

## إصلاح زر العين

السبب كان استعمال inset-inline-end في الأب العربي مع padding-inline-end في input باتجاه LTR. الزر أصبح عمود Grid مستقلًا عن input،وله accessible label ويظل type=button. النص لا يدخل حيز الزر حتى مع Autofill. اختبار المتصفح يقيس مستطيل الحقل والزر ويتأكد من عدم التقاطع بالعربي والإنجليزي،وعند390 و1365px،ويؤكد أن إظهار/إخفاء الباسورد لا يغيّر قيمته.

## الأدلة وحدودها

فحوص Password API تشمل الأدوار الأربعة،رفض اختيار/اختراق role،تقييد قراءة hash،قفل الحساب،CSRF،تغيير الباسورد وإلغاء الجلسات،واستعادة متزامنة أحادية الاستخدام. رحلة E2E تستخدم التسجيل والدخول بالباسورد فعلًا،وتكمل التاجر والدعوات والكاشير والأختام والصرف والتجديد والتعافي والتصدير والدعم.

التحقق النهائي في [checks.json](evidence/implementation/checks.json)،و[رحلة المتصفح](evidence/implementation/browser.json)،واختبار بيئة أول شركة في [manual-demo.json](evidence/implementation/manual-demo.json). البيانات الصناعية داخل DB مؤقتة أوتجار QA في بيئة التطوير،ولا تملأ بيئة مازن الفارغة. ده قبول محلي؛الاستضافة وexternal recovery/email والتحقق بالأجهزة بوابات مستقلة.

## تحديث لاحق في نفس اليوم

الوصف السابق للدعوات والقوالب يسجل المرحلة الأولى. المسار الحالي ينشئ حسابات الفريق الجديدة بإيميل وباسورد يكتبه المسؤول،ويبقي الدعوة للحساب الموجود. أضيفت 6 قوالب ليصبح المجموع 9،ولوجو في التجهيز وHEX/palette وQR مرئي وملف دعم لكل محل ولغة أولى حسب الجهاز. راجع [ONBOARDING-AND-SUPPORT](ONBOARDING-AND-SUPPORT.md) و[MANUAL-DEMO](MANUAL-DEMO.md) للتشغيل الحالي.
