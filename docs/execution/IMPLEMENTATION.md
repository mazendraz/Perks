# التنفيذ الحالي — 2026-11-07

ده وصف السورس اللي اتنفذ بعد مراجعة P00، مش وصف ملفات الـDemo. النسخة الحالية **تطوير محلي متصل بخادم وPostgreSQL**. مفيش نشر تجاري أوتكامل خارجي مفعّل. المالك أكد في نفس الجلسة إن مفيش حسابات خارجية حاليًا.

أُضيفت واجهة جديدة وكروت عضوية وخطوط محلية،والدخول بالإيميل والباسورد لجميع الأدوار. التفاصيل الحالية في [PASSWORD-AND-DESIGN](PASSWORD-AND-DESIGN.md).

## المصدر والتشغيل

| الجزء | المصدر | التنفيذ |
|---|---|---|
| Web | `apps/web/src` | React 19 + TypeScript + Vite، Arabic RTL/English LTR، صفحات مؤجلة التحميل |
| API | `apps/api/src` | Fastify 5، جلسات Cookie وCSRF، صلاحيات تُراجع لكل طلب |
| Worker | `apps/worker/src` | Outbox، leases بفencing، بريد محلي وتصدير خاص وانتهاء طلبات/مكافآت |
| DB | `db/migrations` | PostgreSQL 17، migrations متسلسلة ببصمة SHA256، runtime/auth/worker منفصلة عن migrator |
| قواعد مشتركة | `packages/domain` | حساب العتبة وتطبيع الإيصال ويوم الشراء حسب timezone |
| Contracts وUI | `packages/contracts`, `packages/ui` | عقود Zod مشتركة للمسارات الأساسية وOpenAPI للطلبات والنتائج والأخطاء؛ تغطية المسارات الإدارية الثانوية لسه جزئية |
| أصول المراجعة | `standalone` | الست exports محفوظين من غير تعديل؛ الـMock بتاعهم مستقل عن التطبيق الجديد |

الإصدارات الدقيقة في package-lock.json. التشغيل والأدوار المحلية في [RUNBOOK](RUNBOOK.md). التطبيق على http://127.0.0.1:5173 والـAPI على 4100 وقاعدة Nuqta المستقلة على 55432. أي خدمة أخرى على الجهاز تفضل مستقلة.

## السلوك المتصل بالفعل

- تجهيز تاجر من Wizard بسبع خطوات، مسودات بإصدارات، استكمال بعد إعادة الفتح، وتفعيل ذري قابل للإعادة. تاجر واحد وبرنامج وفروع ودعوات واحدة حتى مع تفعيل متزامن. اللوجو يتضاف من Branding بعد التفعيل؛ رفعه داخل خطوة الـWizard نفسها لسه مش متاح.
- هوية وألوان وثلاث قوالب للكارت، رفع PNG/JPEG/WebP محدود وإعادة ترميز آمنة. الملف خاص لحد اختيار اللوجو للنشر. الـpublic endpoint يقدّم اللوجو المختار بس. التخزين محلي؛ Cloud Object Storage غير مهيأ.
- دعوات بريد مرتبطة بهوية متحقق منها، تدوير وإلغاء التوكن، أدوار وفروع وحدود كمية، إيقاف موظف حي، وحماية آخر مالك. إضافة وتعديل الفروع وفحص حدود الخطة داخل transaction.
- تسجيل عميل ببريد متحقق محليًا، شروط إلزامية مرتبطة ببصمة النص المعروض؛تغيير الشروط أثناء التسجيل يوقف الحفظ لحد مراجعتها من جديد. تسويق اختياري غير مفعّل افتراضيًا، عضوية وكارت محفوظين بالخادم، وكروت متعددة مستقلة.
- QR شخصي حقيقي محدود الصلاحية ومخزّن كـhash؛ ZXing camera path موجود مع إدخال يدوي بديل. الاختبار الآلي استخدم المسار اليدوي وفك صورة QR فعلية، مش كاميرا أوهاتفًا حقيقيًا.
- عملية ختم تضم شراءً فريدًا وoperation وledger وreward grants وprojection وaudit وoutbox في commit واحد. 3 أختام لشراء واحد = زيارة واحدة. الإيصال مشترك بين المسح والطلبات، وتطبيع الأرقام العربية يمنع التحايل بالتنسيق.
- الكارت يظهر مكتملًا عند توفر مكافأة؛ بعد تأكيد الصرف يبدأ رقم دورة جديد في نفس العضوية والسجل. الرصيد الزائد والمكافآت المستقلة لا يُحذفوا. أنيميشن الختم ورسم علامة التأكيد واكتمال المكافأة وتجديد الكارت مرتبطة بتغيّر revision مؤكد؛ reduced-motion يعطل الحركة ويحافظ على الحالة والتنبيه المقروء.
- تأكيد حامل الكارت من حسابه قبل الاستبدال، إعادة فحص الصلاحية والفرع والموظف بعد الأقفال، واستبدال واحد حتى مع طلبين متزامنين. انتهاء الكسب منفصل عن انتهاء المكافأة.
- إنشاء برامج متعددة بحدود خطة تُفحص تحت قفل، وإيقاف واستئناف الكسب بإجراء صريح وسبب. نشر version لا يستأنف برنامجًا موقوفًا. كل شراء يخص برنامجًا واحدًا حتى لو العميل عنده كارتان. نسخة جديدة للبرنامج تحفظ العضويات القديمة على نسختها. snapshot شروط المكافأة وفروعها مايتعدّلش. الـSeed ما يوسّعش فروع نسخة منشورة عند إعادة تشغيله.
- تصحيح تعويضي للعملية الأخيرة الآمنة فقط، بمراجع مختلف وسبب. مكافأة مصروفة أوعملية لاحقة أوتصحيح جزئي يدخل needs_review؛ مفيش تعديل مباشر للـLedger أوحذف حق مكتسب.
- طلب ختم من العميل بكود مطابقة ومدة صلاحية. كاشير الفرع يراجع الإيصال والكمية ويوافق أويرفض. الإلغاء والاعتماد والانتهاء لهم انتقال واحد؛ worker يسجل الانتهاء مرة واحدة كحدث نظام.
- تقارير مباشرة من الوقائع: تسجيل ونشاط وخمول وnever-active وأختام وزيارات ومكافآت وأداء فروع ورجوع عملاء، بفترة وtimezone ووقت تحديث وwatermark. رسم يومي وجدول بيانات بديل، بحث حرفي بالاسم/البريد، تفاصيل وشرائح محفوظة.
- CSV خاص يصدره Worker، بنطاق الفرع والشريحة والبحث نفسه، مع حماية formula injection وانتهاء رابط التنزيل بعد ساعة وإعادة فحص بصمة نطاق الصلاحية عند التجهيز والتنزيل. سحب فرع يمنع تنزيل artifact قديمة، وتعطيل الفرع لا يمنح مالكًا جزئيًا بياناته. Worker ينظف الملفات المنتهية/الملغاة/اليتيمة بعد ساعتين، كل دقيقة وبحدود عمل لكل sweep، مع قفل مشترك مع نشر الملفات وحماية الملفات الصالحة والـleases الحية. سياسة Cloud Storage الإنتاجية بوابة مستقلة.
- كل قطعة QR/NFC لها رابط مستقل وتاريخ تجهيز وشحن وتركيب وإلغاء واستبدال. تنزيل QR أوتسجيل حالات اختبار صناعية مش دليل على تصنيع أوشحن أوتجربة تاج فعلي.
- تشغيل منصة فيه بحث بمرجع العملية وسجل/audit/jobs، health وbalance reconciliation وattempts وsafe retry، وتذاكر دعم وردود وحالات محفوظة. platform_support له قراءة تشغيل محدودة وتذاكر، من غير إدارة التجار أوالتكاملات.

## قواعد العزل والتزامن

الخادم يستمد المستخدم من جلسة متحقق منها؛ merchant ID في الطلب مش تفويض. grant حالي قبل استرجاع نتيجة idempotency؛ حتى GET لنتيجة محفوظة يعيد فحص دور وفرع الأمر الأصلي. القيود المركبة تمنع ربط فرع/حساب/مكافأة بتاجر مختلف، وRLS تمنع runtime من تجاوز tenancy. أدوار التطبيق مش owner/superuser/BYPASSRLS. runtime ما يقرأش TOTP secrets، وauth role ما يغيّرش platform roles.

دليل العملاء والتصدير يراجعوا نسبة الفروع المصرح بها حتى للمالك لو نطاقه جزئي. المالك اللي مصرح له بكل الفروع، بما فيها الموقوفة يشوف التسجيلات غير المنسوبة لفرع؛ غيره يشوف العملاء المنسوبين للفروع المسموحة، وقائمة عضويات العميل نفسها متفلترة حسب نسبة كل عضوية للفرع، مش مجرد السماح بفتح صفحة العميل. عناوين التواصل تُستخرج بدالة ضيقة النطاق، مش SELECT مفتوح من runtime.

الرصيد والمكافآت والزيارات مصدرهم DB. localStorage للغة فقط. sessionStorage يحتفظ بمرجع محاولة الكاشير والإيصال وقت النتيجة المبهمة، من غير توكن العرض أوكود المطابقة. محاولة قرار الطلب تحتفظ بالفعل والإيصال والكمية والتاريخ الأصلي وتستكمل بنفس المفتاح؛ الكود يُدخل من جديد لو مفيش commit. مسودة المنصة غير المحفوظة وخطوتها محفوظتين في sessionStorage مرتبطة بالمستخدم، وتتم إزالتهما بعد الخروج المحفوظ أوالتفعيل. نجاح الواجهة بعد رد commit؛ ضياع الرد أوإعادة فتح الصفحة يسترجع نفس العملية. فشل Provider مايرجعش الـLedger للخلف.

حد الطلبات العام مرتبط بهوية الحساب المتحقق منها، وبـIP للمجهول؛ حدود Login حسب IP وقفل محاولات الباسورد حسب الحساب مستقلة؛OTP/TOTP باقية لفحوص التراجع القديمة فقط. ده يمنع تجميع كاشير وعميل على نفس NAT في حصة حساب واحدة.

## بوابات باقية

P01: managed Auth/external email وrecovery إنتاجي لم يُختبر؛واجهة الدخول الحالية بالإيميل والباسورد لكل الأدوار،دون MFA. Supabase JWT exchange موجود كـadapter مرشح؛ وجوده لا يثبت أن تسجيل الدخول الإنتاجي اكتمل. OpenAPI بقى يصف body/response للمسارات الأساسية (تسجيل، أختام، طلبات، استبدال، مسودات وتفعيل، تفضيلات) من نفس Zod المستخدمة في التحقق، مع headers وstructured field errors. تعميم DTOs الصارمة على المسارات الإدارية الثانوية وتوليد SDK شامل لسه بند مستقل.

P02: Cloud Storage ورفع اللوجو داخل الـWizard. P04/P13: اعتماد مدد حفظ العمليات والـPII وأصول غير التصديرات، وفحص إتاحة وتباين الألوان وscreen reader أوسع. انتهاء جلسة أثناء تعديل المسودة اتجرب في المتصفح: دخول بالإيميل والباسورد مع حفظ المدخلات والخطوة. إنشاء وتحديث وتفعيل المسودة يستعيدوا نفس المحاولة بعد ضياع الرد وإعادة التحميل.

P09: خدمة مراقبة وتنبيهات فعلية وon-call وسياسة PII reveal. P10: حسابات وتفويض إصدار وشهادات وتهيئة Apple/Google، ثم adapter signing/issuance/update فعلي واختبار أجهزة. P11: مزود وقنوات وتكلفة وnotification intents/budgets/campaign dispatch؛ الموجود حاليًا consent/preferences فقط. P12: شروط وأسعار وضرائب وسياسة اشتراك معتمدة ومزود دفع وwebhooks؛ الموجود حدود وخطط يدوية من غير فواتير أوتحصيل آلي.

P14/P15: staging/production وحسابات ودومين وTLS ونسخ احتياطي وتنبيهات وأجهزة وPilot وقبول إطلاق. مفيش بوابة من دول اتعلّمت ناجحة لمجرد وجود UI أوconfig. الحالة التفصيلية في [STATUS](STATUS.md) و[TASKS](TASKS.md).
